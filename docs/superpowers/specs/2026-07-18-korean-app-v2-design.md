# Korean Learning App v2 — Anki-Continuation Redesign (Design Spec)

**Date:** 2026-07-18
**Status:** Approved by user (with amendment: keep Reading + Listening)
**Approach:** Full v2 rewrite, vanilla JS (zero-build), same repo replacing v1 on main.
**Planning model:** Fable (this spec + implementation plan). **Execution model:** Opus subagents.

---

## 1. Problem

The user studies Korean with two Anki decks:

1. **Korean Core 5k** (vocab only) — export at
   `C:\Users\HP\Claude work\Korean\anki-korean-deck\Korean Core 5k - English to Korean.txt`.
   Still ongoing (new cards daily in Anki).
2. **TTMIK Supplement** (vocab + grammar) — export at
   `C:\Users\HP\Claude work\Korean\anki-korean-deck\TTMIK Supplement.txt`.
   **Fully studied.** 2,300 notes covering TTMIK Levels 1–3 completely
   (L1: 25 lessons, L2: 30, L3: 29). ~709 distinct vocab words, ~34 particle/pattern
   cards, ~1,550 graded sentences. Notes are tagged `TTMIK-x.yy` (some `KGIU-x.yy`).

v1 of the app only knew about deck #1. Consequences:

- **Grammar overlap:** ~9 of v1's 26 "Level 4–5" lessons re-teach grammar the
  TTMIK deck already covered (수 있다, 못, 고 있다, 아/어 주다, 보다/제일, 네요,
  것 같다, 아/어야 되다, …).
- **Vocab leakage:** ~150–190 TTMIK words (가능하다, 걱정하다, 결정하다, …) are not
  in Core 5k and could appear as "new" cards.
- v1 has never been used by the user — **no progress exists; no migration needed.**

## 2. Product concept

**The app is what comes after Anki.** Anki owns TTMIK L1–3 grammar review and
Core 5k vocab. The app owns everything beyond:

- **TTMIK Level 4–5 grammar lessons** (the literal next lesson after the deck ends)
- **Post-5k vocabulary cards** (continuation deck, Anki-style SRS)
- **Dictation practice** built from the 1,550 deck sentences the user already knows
- Reading passages + podcast listening (carried over from v1)

**Daily flow (Today screen):** ① next grammar lesson step (new or review due) →
② new-word cards due → ③ one dictation round. Completing the flow = streak day.

## 3. Curriculum

- Lesson sequence follows the **actual TTMIK Level 4 and Level 5 lesson lists**.
  These MUST be verified against the official TTMIK curriculum (web lookup) during
  implementation — not written from model memory.
- Lesson **content is original** (own explanations, own example sentences). Only the
  sequence/grammar-point list follows TTMIK. No TTMIK text is copied.
- **Dedup rule (grammar-point granularity):** a TTMIK L4–5 point is skipped or
  compressed to a one-line "already known" note if either
  (a) the deck has notes tagged with that point's lesson (incl. forward tags like
  `TTMIK-4.2`), or (b) the pattern appears in ≥5 deck sentences.
- **Bridge panel:** each lesson embeds 2–3 sentences *from the user's own deck*
  that contain prerequisite grammar the new point builds on ("known-pattern
  reference"). Selected by tag/pattern match from `ttmik-sentences.js`.
- **Lesson vocab** uses only words not in (Core 5k ∪ TTMIK deck words ∪ earlier
  lesson vocab).
- Lesson body keeps v1's proven 5-step flow:
  Grammar → Vocab → Examples → Quiz → Practice, plus pitfalls ("common mistakes").

## 4. Content data layer

```
content/
  curriculum.js        hand-written: [{id:"4.01", ttmik:"L4 Lesson 1", title, point,
                       status:"new"|"known"|"compressed", canDo}]
  lessons/l4.js        hand-written lesson bodies, one array per level
  lessons/l5.js        (same object shape as v1 lessons for easy hand-editing)
  known.js             GENERATED — known-word index: Set-ready arrays
                       {ttmikWords:[709], core5k:[...]} parsed from both exports
  ttmik-sentences.js   GENERATED — [{ko, en, lesson:"2.17", tags:[...]}] ×~1,550
                       (HTML stripped, [sound:] refs dropped, romanization dropped)
  readings.js          ported from v1 as-is
  podcasts.js          ported from v1 as-is
  wordsnext.js         REGENERATED — continuation vocab; exclusions now include
                       TTMIK deck words
tools/
  build_from_anki.py   NEW single pipeline: parses both Anki .txt exports →
                       emits known.js + ttmik-sentences.js. Deterministic, rerunnable
                       whenever the user re-exports a deck.
  build_wordsnext.py   EXTENDED — exclusion source becomes known.js (Core 5k +
                       TTMIK words) + v2 lesson vocab; v1's words5k.js is NOT
                       shipped in v2, so the tool must no longer read it. BLOCK
                       list and MY_GLOSS overrides kept per its docstring.
```

Rules: generated files carry a `// GENERATED by tools/... — do not hand-edit`
header. Hand-written content files keep v1's copy-paste-a-lesson editability.

## 5. App architecture (vanilla JS v2, zero-build)

- **ES modules** (`<script type="module">`); no `window.*` globals, no bundler.
  Open `index.html` → works. Content files are ES modules too (`export const …`),
  imported statically so the service worker can precache a fixed file list.
  (Note: `file://` blocks ES modules in some browsers; primary usage is the
  GitHub Pages URL / installed PWA. For local dev, `python -m http.server` or the
  preview pane suffices — document this in the README.)
- Modules (one concern each):
  - `js/router.js` — hash router, 4 top-level routes + sub-views
  - `js/store.js` — localStorage wrapper, all keys namespaced `kov2.*`;
    JSON export/import backup (no cloud sync in v2)
  - `js/srs.js` — ONE SM-2-style scheduler shared by cards and lesson reviews
    (v1 had two separate schedulers); daily new-card cap (default 15, adjustable);
    lag-200 second-direction rule and same-day burying for card pairs (per v1
    Cards design in docs/superpowers/specs/2026-07-05-anki-cards-tab-design.md)
  - `js/grader.js` — forgiving exact-match + char-diff feedback for typed answers
    (port v1 logic)
  - `js/tts.js` — Web Speech Korean voice, speed control (port v1)
  - `js/views/*.js` — one module per screen: today, syllabus, lesson, cards,
    dictation, reading, listening, me
- **PWA:** manifest + service worker cache-first from day one; fonts vendored
  (no external requests when offline).
- **Dropped from v1:** Firebase sync, mock-TOPIK exams, Words-tab browsing as a
  separate tab (word browsing lives inside Practice → Cards deck list),
  conjugation drills tab (conj drills fold into lesson quizzes where relevant).

## 6. UI — mobile-first, 4 bottom tabs, dark theme kept

| Tab | Contents |
|---|---|
| **Today** | Daily flow with progress ring: lesson step → cards due → dictation round; streak |
| **Learn** | Syllabus (TTMIK L4–5 list, ✓/current/locked) + lesson player |
| **Practice** | Cards (SRS deck), Dictation library, Weak items, **Reading**, **Podcasts** |
| **Me** | Streak calendar, 30-day retention strip, settings (TTS speed, new-card cap), backup export/import |

- Bottom tab bar, thumb-reachable, 44px+ touch targets; layouts designed at 375px
  first, desktop is the adaptation.
- Dark navy theme retained (v1 palette as starting point).

## 7. Feature specs (summary)

- **Dictation:** pick sentence (filterable by TTMIK level), TTS plays at chosen
  speed, user types, char-diff grading; wrong answers join the weak pile; feeds
  streak + retention stats.
- **Cards:** v1 Cards-tab behavior preserved (Again/Hard/Good/Easy, undo, bury
  partner direction same day, KO→EN leads EN→KO by 200) on the regenerated
  wordsnext list.
- **Lesson quizzes/practice:** type-the-Korean and listening questions
  auto-generated from lesson vocab + sentences (port v1 generators); no multiple
  choice except Reading comprehension.
- **Weak items:** any wrong answer anywhere (quiz, cards, dictation, reading)
  enters the pile; one correct answer retires it.
- **Retention stats:** every graded answer logs to a daily right/wrong store →
  30-day accuracy strip on Me.

## 8. Verification plan

- After each build phase: open in browser preview, click through the affected
  flow, check console clean, check 375px viewport.
- Content checks: TTMIK L4–5 lesson list cross-checked against official source;
  `known.js`/`ttmik-sentences.js` spot-checked against the raw export (counts,
  random samples); regenerated `wordsnext.js` verified to contain zero words from
  either deck.
- Final pass: full offline test (service worker), PWA install check, Lighthouse
  mobile sanity.

## 9. Build order (each phase = one Opus-dispatchable chunk)

1. **Content pipeline** — `build_from_anki.py`, `known.js`, `ttmik-sentences.js`,
   extend + rerun `build_wordsnext.py`
2. **Curriculum research + `curriculum.js`** — verified TTMIK L4–5 list, dedup
   status per point (needs web access)
3. **App shell** — index.html, router, store, theme CSS, tab bar, PWA scaffold
4. **Lesson content + player** — l4.js/l5.js lesson bodies (batched), syllabus +
   lesson 5-step player + quizzes/practice
5. **Cards** — SRS + card UI on regenerated wordsnext
6. **Dictation** — library + drill + grading
7. **Reading + Listening ports**
8. **Today flow + Me** — daily orchestration, streak, stats, backup
9. **Polish + offline/PWA verification**

v1 is replaced on `main` in one switchover commit at the end (v1 remains in git
history). GitHub Pages URL unchanged.

## 10. Out of scope (explicit)

- Cloud sync (Firebase) — JSON backup only
- Mock TOPIK exams
- Bundled mp3 audio (TTS only; deck `[sound:]` refs are dropped)
- TTMIK Level 6+ (future phase; curriculum.js structure must allow appending)
